# lhg-paper-audit：投稿前自查 + 返修应对

> ## 学术诚信提醒（本 skill 内置）
>
> 自查清单查的是**格式与完整性**，查不出"引用是否真读过""数据是否真实"。
> 这两项是作者的终身责任，任何工具都代替不了。
> 收到"建议补实验"的审稿意见时，不许编造实验结果——做不出来就诚实说明局限。

> 目标：blocker 清零再投稿；收到审稿意见后 48 小时内给出分类与返修策略。
> 核心纪律：**先跑脚本，再人工核查，最后才点提交**。

## 1. 何时使用

- 全文写完、准备投稿 → 第 2 步自查清单
- 收到审稿意见（大修/小修/拒稿重投）→ 第 4 步返修流程
- 导师说"再检查一遍"但不知道查什么 → 第 2+3 步

## 2. 输入与输出

**输入**：论文目录（含 `sections/`、`references.bib`）。

**输出**：自查报告（blocker/warning 清单 + 修复建议）或返修信初稿。

## 3. 投稿前自查清单（三层）

### 3.1 脚本层（确定性，必跑）

```
python3 <插件目录>/scripts/audit/paper_audit.py --target <论文目录> --format text
```

| 规则族 | 查什么 | 级别 |
|---|---|---|
| PP-ABS | 摘要缺失/过短；摘要超长（>350 词） | blocker / warning |
| PP-KW-001 | 摘要缺少关键词 | blocker |
| PP-SEC-001 | 引言/方法/结果/讨论缺失或近乎空白 | blocker |
| PP-CITE-001 | 幽灵引用（正文引用了，参考文献里没有） | blocker |
| PP-CITE-002 | 悬挂文献（参考文献从未被正文引用） | warning |
| PP-FIG-001 | 正文提到图N/表N但无对应图题 | blocker |
| PP-FIG-002 | 图片插入缺少图题/编号 | warning |
| PP-LANG-001 | 口语化表达 | warning |
| PP-ETH-001 | 无利益冲突/伦理声明 | warning |

blocker 必须清零；warning 修完再投（别赌审稿人看不见）。

### 3.2 人工核查层（脚本做不到的）

1. **引用真实性抽查**：随机抽 10 条，确认读过原文、论点对得上。
2. **数字三遍核对**：摘要=正文=图表，同一数字完全一致。
3. **作者信息**：顺序、通讯作者、单位、基金号，与投稿系统一致。
4. **期刊格式**：参考文献格式、图表位置、字数上限、附加项
   （Highlights/Graphical Abstract/cover letter 要求）。
5. **AI 披露声明**：按期刊要求写好，放对位置。
6. **一稿一投确认**：确认没有同时投其他期刊（红线，自查）。

### 3.3 终稿朗读层

全文大声朗读一遍（或用 TTS 听一遍）：读不顺的句子重写；
发现"这段好像在凑字数"的，删掉——审稿人对凑字数的容忍度为零。

## 4. 审稿意见返修流程（四步）

### 4.1 逐条编号

把所有审稿人的意见按"审稿人-序号"编号（R1-Q1, R1-Q2, R2-Q1…），
编辑的意见单独编号（E-Q1…）。一条意见含多个问题就拆成多条。

### 4.2 分类（三类，决定策略）

| 类别 | 特征 | 策略 |
|---|---|---|
| A：同意修改 | 指出的问题确实存在 | 直接改，正文标出修改处 |
| B：部分同意 | 问题存在但审稿人建议的改法不合适 | 按自己的方式改，信中解释为什么这样改更好 |
| C：礼貌反驳 | 审稿人误解/要求不合理 | 先肯定审稿人的出发点，给证据+引用，请求维持原状 |

**纪律**：C 类不超过总数的 1/3。通篇反驳 = 拒稿快捷键。

### 4.3 point-by-point 回复模板

```markdown
尊敬的编辑与审稿人：

感谢您宝贵的意见。我们已逐条修改，修改处在正文中以 [黄色高亮/修订模式] 标出。

---

**R1-Q1**（审稿人原话引用）：
> "……"

**回复**：感谢指出。我们已 [具体修改内容]，见正文第 X 页第 Y 段 / 图 N。
[如为 C 类：我们理解您的担忧，但基于以下两点维持原状：1)……（证据）；2)……（引用）。
我们已在讨论部分第 X 段补充了相关说明。]

---

**修改总结**：本次共修改 X 处，其中正文 Y 处、图表 Z 处，未改动核心结论。
```

### 4.4 返修信铁律

1. **语气**：感谢开头，每条先肯定再回应，不许出现"你错了""你没看懂"。
2. **可定位**：每条回复必须给出"正文第几页/图几"的定位，不许"已修改"三个字打发。
3. **诚实**：补不了的实验/做不到的要求，直接说"受 XX 限制未能完成，
   已在局限性部分说明"，不许编数据。
4. **时限**：大修尽量在截止前一周提交，留出 buffer 应对系统问题。

## 5. 反模式（不许这么干）

- **blocker 没清就投稿**："审稿人应该看不出来"——看得出来，而且第一印象就没了。
- **返修信只说"已修改"**：没有定位的回复 = 没回复，编辑会打回来。
- **通篇反驳审稿人**：C 类超过 1/3，基本等于告诉编辑"我不想改"。
- **编造补充实验**：学术生涯自杀行为，没有之一。
- **把审稿意见晾三个月**：大修拖延 = 告诉编辑"这工作我不重视"。

## 6. 自检与反馈

**质检门（投稿前）**：

- [ ] 审计脚本 blocker 数量 = 0？
- [ ] 引用抽查 10 条，全部读过且对得上？
- [ ] 关键数字三处一致？
- [ ] AI 披露声明按期刊要求写好了？
- [ ] 一稿一投已确认？

**质检门（返修时）**：

- [ ] 所有意见已编号，无遗漏？
- [ ] C 类（反驳）不超过 1/3？
- [ ] 每条回复都有正文定位？
- [ ] 语气检查：全文无"你错了"类表述？

**标准冒烟用例**：用插件 `fixtures/paper-bad` 跑审计脚本，
确认 9 类埋点规则全部命中且退出码非零；用 `fixtures/paper-good`
跑，确认零 blocker 且退出码为 0。

**发现问题**：到本仓库提 issue（标题前缀 `[lhg-paper-audit]`），
描述：规则 ID（如 PP-FIG-001）、误报/漏报的原文片段。
